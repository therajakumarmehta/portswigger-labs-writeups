# Lab Name
Blind SSRF with out-of-band detection

## Vulnerability
Blind Server-Side Request Forgery (SSRF)

## Objective
Trigger a server-side request to an attacker-controlled Burp Collaborator domain and confirm the SSRF through DNS and HTTP interactions.

## Entry Point
Referer header

## Exploitation Type
Blind SSRF / Out-of-Band (OAST) Detection

## Methodology
1. Visit any product page, intercept the request using **Burp Suite**, and send it to **Burp Repeater**.

2. In **Burp Repeater**, select the **Referer** header, right-click it, and choose:

```text
Insert Collaborator Payload
```

This replaces the original domain with a Burp Collaborator-generated domain.

3. Send the modified request.

4. Go to the **Collaborator** tab and click:

```text
Poll now
```

5. If no interaction appears immediately, wait a few seconds and click **Poll now** again because the server-side request may be executed asynchronously.

6. Observe the **DNS** and **HTTP** interactions generated by the application server.

7. These interactions confirm that the application server made a request to the Burp Collaborator domain, proving the Blind SSRF vulnerability.

## Payload Used

```http
Referer: https://YOUR-COLLABORATOR-ID.oastify.com
```
## Result
Successfully triggered a Blind SSRF and confirmed the server-side interaction through DNS and HTTP requests received by Burp Collaborator.

## Impact
- Server-side requests to attacker-controlled domains
- Potential access to internal services
- Internal network reconnaissance
- Possible further exploitation depending on accessible services

## Mitigation
- Validate and restrict user-controlled URLs and headers.
- Use strict allowlists for outbound requests.
- Block unnecessary outbound network access.
- Prevent access to internal and private network ranges.
- Monitor unusual DNS and HTTP requests originating from application servers.

## Learning
Blind SSRF occurs when the application makes a server-side request but does not return the response to the attacker. In this lab, the **Referer** header is used as the SSRF input. Burp Collaborator provides out-of-band detection, where the resulting **DNS and HTTP interactions** confirm that the vulnerable server processed the attacker-controlled domain.
